# ハーネスチューニング

![夜のプールサイドで、白い翼の天使と跪く人が向き合う](assets/hero.jpg)
**ハーネスが1リクエストで送るトークンを減らす。**

全部を背負わない。必要なとき、思い出す。

モデルの良し悪しは、送った文脈の量では決まりません。ハーネスチューニングの目的は1つ —— **ハーネスが1リクエストで送るトークンを減らす**こと。ただし減らすというのは、消すことではありません。**必要になったときに思い出せる形に置き直す**。ここが核です。

## 核: 常時載せるのは「思い出せる手がかり」だけ

エージェントは、答えを書く前に毎回かならず自分の指示面（スキル・記憶・人格・ツール）を読みます。全部をそこに置くと、使わない日もその分を払い続けます。かといって削りすぎると、必要な場面で使えません。

| 区分 | 置くもの |
| --- | --- |
| 常時載る（手がかり） | 名前と一行の説明、短い事実だけ。これだけで「ある」と分かる |
| 使うとき載る（本文） | 手順・定義・参照先。要ると決めた瞬間に読みに行く |
| 載せない（要らないもの） | 使わない機能、古くなった事実、終わった作業。置き場所を外へ出す |

## LLMにどう読ませるか

4つの面それぞれに「常時」と「使うとき」の分け方があります。

### Skills（手順）

- **常時**: 索引。載るのは名前と説明の一行だけ。
- **使うとき**: 本文（SKILL.md）。細部は references へ分け、そこまで要るときだけ読む。
- **書くコツ**: 説明の一行目を「いつ使うか」で書く。索引で見つかるかどうかは説明で決まる。

### Memory（持ち越す事実）

- **常時**: 短い事実だけ。セッションをまたいで毎回載る。
- **使うとき**: 手順はスキルへ、長い記録は外へ。過去の会話は検索して思い出す。
- **書くコツ**: 変わった事実は足さずに置き換える。同じことを二度書かない。

### Tools（呼べる機能）

- **常時**: 名前と一行。引数まで含む定義は載せない。
- **使うとき**: 検索して定義を読み、それから実行する。
- **書くコツ**: 迷ったら「呼んだときだけ載る」側に置く。使わない機能は最初から載せない。

### 会話とツール結果（伸びる側）

- **常時**: 直近の往復は保護する。
- **使うとき**: 古い部分から落とす。安い順に —— 決定的な刈り込みを先に、要約は最後の手段。
- **書くコツ**: 要約は情報を落とす。落とす前に、機械的に切れるところを切る。

## 効く順番

- **固定費（毎回載る分）から** — 索引・記憶・人格・ツール一覧。ここを削ると、すべてのやり取りが軽くなる。
- **次に可変費（会話とツール結果）** — 長い作業ほど効く。短い会話では差が出ない。
- **常時載る部分は、むやみに書き換えない** — 同じ前置きは繰り返し読むほど安くなる。頻繁に変えると、削った以上に高くつくことがある。

## 減らしたあとに確かめる

減らすこと自体は簡単です。難しいのは、減らしても必要になったとき見つかること。

- **量（減ったか）** — 実際に送られたリクエストで測る。見積りや索引の行数ではなく、送った実物で。
- **到達率（見つかるか）** — 必要になった場面で、実際にたどり着けたか。使えていた例がまだ使えるかを、変えた前と後で同じ手順で確かめる。

## やらないこと

- **境界** — 公開するかどうか、課金、資源の停止、正本の書き換えは利用者が決めて実行する。整える側は読み取り・提案・下書きまで。
- **混ぜない** — 危険や破損を止めるための停止と、軽くするための停止は別の操作。軽量化の口実にしない。

## 受け継ぐ規則

- 同じ内容は1箇所に置く。読み手に二度読ませない。
- 戻せるようにしてから触る。戻れない変更はしない。
- 減らしたら、思い出せるかを測る。量だけ見て削らない。
