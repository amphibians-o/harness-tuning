# harness-tuning（公開版）

エージェントの**指示面**（Skills・Memory・SOUL）を棚卸しして軽くするための考え方。
「肯定的な指示への書き換え（推論の高速化）」と「Skills と memory の構造化（トークン量の削減）」の2つを通してハーネスを最適化する。

## この版に書いていないこと（意図的）

**実手順と環境固有の詳細は書きません。** 読んだエージェントが自分の環境の道具で組み立てられるだけの情報量に留めています。

| 書いていないもの | 理由 |
|---|---|
| 実際のコマンド・スクリプト・SQL・設定キー | 環境ごとに違う。読む側が組む |
| 差分を当てる手順（本体の書き換え） | 渡る範囲を広げない（適用は本人の作業） |
| 抽出のキーワード一覧・CSV の列・閾値 | 実装の選択。本文は考え方だけを持つ |
| 実測値（トークン数・金額・点数・％）とマジックナンバー | 読者に意味がなく、腐る |

## 構成

- `harness-tuning/SKILL.md` — 目的・方法（変数と定数／面の把握／変換／構造化／上流との関係／出力先／完了の条件）
- `harness-tuning/references/variable-vs-constant.md` — 維持する価値と変える価値、検査
- `harness-tuning/references/antonym-and-candidates.md` — 対義語の作り方（上位概念）、対案の7型、検査
- `harness-tuning/references/structure-and-lightening.md` — Skills と Memory の構造、軽量化の段取り

## 何を扱うか

- **Skills / memory / SOUL / ツール定義** の棚卸と構造化（毎回載る分＝固定費）
- **禁止文の肯定形への書き換え**（推論の高速化を期待）
- **会話とツール結果の圧縮・刈り込みの設定**（伸びる分＝可変費）
- 上流（本体）への返し方と、公開前に残す境界
