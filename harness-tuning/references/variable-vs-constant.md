# 変数と定数（維持する価値と、変える価値）

決め方は SKILL.md の「1 変数と定数」。**表と検査はこのファイルが正本。**

## 定数 — 根拠があり、依頼するユーザーが値を維持するメリットを持つもの

| 種類 | 例 | 維持するメリット |
|---|---|---|
| 権限の境界 | 公開・課金・資源停止・正本の書き換えは利用者が行う | 境界が人や状況でぶれない |
| 完了の定義 | 動く成果物＋実際に走らせて確かめた結果 | 終わりの基準が一致する |
| 優先順序 | 迷ったら 真実 → 善 → 美 | 衝突の解決則になる |
| 真偽の規律 | 引用か実行IDを添える。添えられない作業は未実施として報告する | 依頼者が結果を検算できる |
| 工程の型 | 承認 → 生成 を混ぜない | 手戻りの型を防ぐ |
| **常時あるのが前提の道具** | 承認を求める道具・記憶を書く道具 | 使われなくなると困る（遅延化の対象にしない） |
| **対象の範囲** | この道具は何でも屋ではない／安全・公開・課金・資源は書き換えない | 用途が広がらない |

## 変数 — 構造があり、環境や情報が変わったときに値を変えるメリットがあるもの

| 種類 | 書いてはいけない形 | 書くべき形（構造） |
|---|---|---|
| 本数・上限 | 「◯件まで」「◯k字以内」 | 上限を持つ検査スクリプトか設定のキーを指す |
| 環境依存の数 | 台数・容量・件数を直書き | 登録ディレクトリや検出カタログを正本にする |
| パス・モデル名・ポート | 直書き | ホームの環境変数・プレースホルダ・設定のキー名を指す |
| レート値・係数 | 数値や換算係数を本文に写す | 定義ファイルを指す（推定式を本文に置かない） |
| 上位の階層 | 「まずこのツリーを見る」 | どのツリーを上に見るかはミッションで決まる |
| 読む本数 | 「◯本だけ読む」（上限として読まれる） | 依頼に応じる。他のツリーの構造を使うことは妨げない |
| 判定の閾値・類似度 | 「◯割前後」の目安 | 同一バッチ内の相対比較だけで判定し、値を本文に書かない |
| **ツールの名前・説明・スキーマ** | スキーマや引数を本文へ写す | 「そのツールが何をするか」と「どこが正本か」を書く |
| **ツールの数と遅延の一覧** | 「◯個まで」「◯個を遅延」 | 一覧そのものを設定に持たせ、本文は判定基準だけを書く |

### 成長するものは変数として扱う

増えていく対象（スキルの本数、記憶の項目、**ツールの数**、対応するモデル、案件、詳細ファイルの中身）は**増えることが前提**。その時点の値を固定して書くと必ず腐る。

- 書くこと: 「どこが正本か」「どう増えるか（増えたときに何をするか）」。
- 書かないこと: 現在の件数・合計・上限。
- **増えることを異常として扱わない。** 「増えすぎを抑える」より「増えても壊れない置き場と経路を持つ」を選ぶ。

### 詳細のMD（details などの置き場）

中身が増え続ける置き場。件数や長さを本文に書かず、**在処の行**と検索で辿る。詳細は**原文のまま**置く（要約すると正本が二つになる）。

## 検査（書いた後・改訂した後）

1. **維持する価値があるか**: その値は、利用者にとって維持する側にメリットがあるか（定数なら断定で書く）。
2. **変える価値があるか**: 環境や情報が変わったときに変える側にメリットがあるか（変数なら決まり方を書く）。
3. **成長するものではないか**: 増えていく対象を、その時点の値で固定していないか。
4. **境界は誰が決めるか**: 文書から推定できない境界は**利用者に問い合わせて決め、定数として書く**（「利用者が行う」を先に書く）。
5. **参照先が実在するか**: 存在しないファイル・スキル・ツールを指していないか。指す場合は「無ければ一次資料へ降りる」を併記する。
6. **同じ設問での回帰**: 改訂したら同じ設問を同じバッチで掛け直す。バッチをまたいだ数値は比較しない。

- 「だけ」「まで」「すべて」のような**上限語は手掛かりまで**。語の一致では確かめられないので、探索が止まっていないかは到達率で確かめる。
- 適用の具体（どこへ移すか）は SKILL.md の「6 出力先」が正本。索引の構造は `references/structure-and-lightening.md` が正本。
