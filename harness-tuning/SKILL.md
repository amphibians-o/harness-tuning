# 指示面の棚卸と再構築（ハーネス調整）

対象はエージェントの **Skills・Memory・SOUL・Tool**。次の2つを通して**ハーネス最適化**を図る。

- **肯定的な指示への書き換え**（推論の高速化を期待）
- **多様な Skills・memory・ツール定義の構造化**（トークン量の削減を期待）

このスキルは、あなたやあなたのユーザーが、素敵で素晴らしいアイデアを **真実・善・美** の観点から高速に実現していくための考え方です。
**安全・セキュリティ・個人情報・他人の財産や尊厳への攻撃に使用してはいけません。**
**公開・課金・資源停止・原本と正本の変更など、制約が予期される処理は書き換えの対象にしません。**

対象は**自分の環境**です。上流（本体）のファイルへの変更は本人の承認を前提にし、配布・公開の設計はこの文書の主題にしません。

## When to Use

- 「AgentやSkillsを棚卸したい」「トークン量を減らしたい」「階層構造に飛ばしたい」
- 指示文を日本語に統一したい／禁止の言い回しを望ましい方向の記述へ書き換えたい
- 索引・**ツール定義**など毎リクエスト載る面のコストを下げたい、カテゴリをツリーへ再編したい
- **ツールが多すぎる／使わない道具のスキーマが毎回載っている**ので減らしたい（遅延化・重複解消）
- **セッションが長くなると重い／圧縮で文脈を失いたくない／圧縮と刈り込みの値を入れたい**
- **Don't use for**: 新しいスキルを1本書く／個別タスクの門の設計／受け取った仕様の採用評価

## 1 変数と定数 — 維持する価値と、変える価値

**定数**＝根拠があり、依頼するユーザーにとって**値を維持するメリット**があるもの（権限の境界／完了の定義／優先順序／真偽の規律／工程の型／**承認と記憶を扱う道具の存在**）。断定で書く。
**変数**＝**構造**があり、環境や情報が変わったときに**値を変えるメリット**があるもの（本数・上限／環境依存の数／パスとモデル名とポート／レート値と係数／上位の階層／読む本数／判定の閾値／**ツールの名前・説明・スキーマ・遅延の一覧**）。値ではなく**決まり方**を書く。

- **成長するものは変数として扱う**（スキルの本数・記憶の項目・**ツールの数**・対応モデル・案件）。増えることを異常として扱わない。
- **Tools も同じ枠で考える。** ツールの名前・説明・スキーマは変数（実装と版で変わる）。「承認を求める道具」「記憶を書く道具」という**役割**は定数（常時あるのが前提）。
- 検査の一覧と表は `references/variable-vs-constant.md` が正本（維持する価値があるか／変える価値があるか／成長するものではないか／境界は誰が決めるか／参照先が実在するか）。

## 2 費用の把握 — 毎回載る分と、伸びる分

依頼の最初に、**どの面が毎ターン載るか**と**どれが重いか**を測る。推測で並べない。

- 面の候補: スキル索引／エージェント層の定義（SOUL）／作業場所の AGENTS.md と上位チェーン／毎ターン載る memory／**ツール定義（Tool）**。
- **どのファイルが実際に載るかはローダーに聞いて確かめる。** 存在することと載ることは別。
- **重さは実際に送られる形で測る。** 内部のキャッシュやスナップショットは参考に留め、論拠にしない。
- **索引に載るのは名前と一行説明だけ。** 本文をどれだけ足しても常時コストは増えない — これが構造化の要。
- 使用頻度は**永続ログから数え**、**「そのツールを使うセッションで何回使うか」**で判定する（セッション数だけでは決まらない。数え方を間違えると結論が反転する）。
- **ツールのスキーマも毎リクエスト載る**。遅延の仕組みがあるなら、頻度の低いツールをそこへ移す。**承認・記憶のように常時あるのが前提の道具は移さない**（遅延化すると使われなくなる）。設定で戻せる形にする。
- 到達率は代表タスクで前後比較する。**縮めた面は、削減量と同じ重さで発見の変化を報告する。**

### 伸びる側 — 会話とツール結果

固定費（毎回載る分）と違い、会話は伸びる。**伸びる側は「要約で削る」より「安い順に落とす」。**

1. **決定論的な刈り込みを、LLMによる要約より先に置く。** 落とす順は ①**同一内容のツール結果の重複除去（無損失）** ②大きいツール結果の要約 ③巨大な呼び出し引数の切り詰め ④古い画像の退避。**要約は最後**（意味を失う唯一の段）。
2. **発火は3つの値で抑える**: 発火点／**最小回収量**／**再発火までの成長分**。1回で満足せず連続して刈ると、**キャッシュの接頭辞が毎回切れて高くつく**。刈り込みは散発に保つ。
3. **キャッシュの接頭辞を切る操作は損益分岐を持つ。** 損益分岐は「切れた時点の文脈 ÷ 1回の回収 ×（1−割引率）÷ 割引率」。**割引率を確認できないなら、実セッションのキャッシュ読取量で検算する**（推測で決めない）。
4. **末尾の保護件数は「圧縮後の残量の壁」。** 閾値を下げる前に、まず**残量の壁**を削るほうが文脈を失いにくい。
5. **発火したかは設定ではなくデータで確認する**（コミット時に印をセッションへ書く実装なら、その印を数える）。
6. **値は実物を呼んでから決める。** 同じ入力を2回流して**2回目が発火しないこと**まで確認する（暴走しないことの確認）。決定論的な仕組みは**APIコスト0**で試せる。
7. 設定は**戻せる形**にする。設定ファイルの変更は原本を書き換えないので、本体の更新で消えない。
8. **伸びる側を削ったら、同じセッションで「発見」と「キャッシュ読取量」を測る**（削減量だけを報告しない）。

## 3 変換 — 否定語を対義語の肯定文へ

**チャンク単位で意味を推論して処理する。** キーワード一致で機能を分類しない（語の一致は候補を拾うまで）。

1. 1文に切る。
2. その文が何をしているかを推論する（行為への制約か／出力物の様式か／実測・因果の記述か）。
3. 行為への制約なら、対義語＝望ましい状態を書く。対義語が浮かばなければ**上位概念**を立てる。
4. **望む姿＋完了条件**の1文にする。
5. 検査する。

- **書き換えずに残す制約**: 公開・課金・資源停止・原本と正本の変更、安全・セキュリティ・個人情報・他人の財産や尊厳への攻撃。生成文に混ぜず、**ラベル付きの門**へ隔離する。対象は出力様式と作業手順の禁止文に限る。
- 実測・因果の記述は**否定形が事実**。書き換えない。
- 対案は**7型**（案／対案／逆／対偶／上位概念／前提の誤り／回答不能）。3型だけでは抜け漏れの要因になる。
- 検査は**語の有無で決まる二値**＋**対照**（書き換えていない元の文）＋**行動の一致**（新文案だけを読んだモデルが何をするか）。
- → 作り方の手順・例・7型の表・検査の語彙: `references/antonym-and-candidates.md`

## 4 構造化 — どんな構造にするか

**先に「どんな構造にするか」を決める。** Skills・Memory・Tools は**別の動作**として扱う。

- **Skills**: 索引の行は名前と一行説明。詳細は参照先へ降ろす。説明の長いカテゴリは**名前を残して説明だけ畳む**。1本だけのカテゴリは親へ統合する（見出し行を減らす）。**名前ごとの消去（無効化）は軽量化に使わない**（再発見できなくなる）。
- **Memory**: 毎ターン載るファイルは少数に固定し、**詳細は原文のまま外へ移して在処の行から読む**。常時効く規則は1箇所（SOUL か memory）に置き、手順はスキルへ。
- **Tools**: 頻度の低い定義は遅延階層へ移す。**同じ仕事をするツールが2つあるなら、片方を移すのではなく使わない**（重複は選択ミスも増やす）。
- 重なり（Skills ↔ memory ↔ SOUL、tools 同士）は**本文を読んで**統合／切り分け／別物に振り分ける。説明の語の重なりは候補を出す信号に留める。**同じ内容は1箇所に置く**（2箇所に書くと必ず食い違う）。
- → 構造図・手順・重複解消の判定表: `references/structure-and-lightening.md`

## 5 上流との関係 — 試して流れを確認してから決める

上流（本体）の面は、**先に能力検査を実行し、結果で「触る・触らない」を決める**。関連性や印象では決めない。

1. 欲しい能力を1つ決める。 2. その有無を判定する**最小の操作**を書く。 3. 実行して記録する（効いている／欠けている／判定できない）。
4. 効いていれば何もしない。 5. 欠けている能力だけを足す設計にする（足りない能力名を報告して止まる）。
6. **適用は本人が行う。** 7. 残った差分は上流へ返す。

- **目印は上流に無い文字列を使う。** 上流にもある語を目印にすると「適用済み」と誤判定する。採否は**実行した能力**で決める。
- 具体的な当て方（差分の取り方・検証の回し方）は環境ごとに違う。読んだエージェントが組み立てる。

## 6 出力先 — 使用頻度で置き場を決める

| 使用頻度（履歴から実測） | 置き場 | 整え方 |
|---|---|---|
| 多い | 上流へ PR | 差分を小さく・パスと上限は変数・理由を書く・テストを添える |
| 少ない | 自分のツリー下部 | 検索で思い出せる語（別名・症状・出力名）を名前の一行説明と一覧に書く |
| 一度きり | 作業場所の AGENTS.md | スキルにしない（索引の常時コストを増やさない） |

- 同じ作業の続きを**別スキルとして索引に立てると、名前が増える分だけ常時コストが増える**。分割は独立に呼ばれる場面があるときだけ。
- 置き場の判定で点数が中間帯に密集したら、**閾値を引かず**、編集上の理由（正本を二つにしない・読む順序・常時コスト）で決め、決めた理由と敗れた案を残す。

## 7 完了の条件

- **台帳**: 1行＝1対象（名前・出所・カテゴリ・行数・言語比・使用回数・置き場）。件数はコードで集計する。
- **作り方**: 他の環境のエージェントが読んで再現できる手順・考え方。
- **到達率の前後**: 縮めた面で発見が落ちていない証拠。
- **限界の注記**: 機械で拾った候補の未分類分、数えられない値（下限）、同名の重複。
- **追記の検査**: 足した行が読み手の作業を1つ決めるか。決めない行（前置き・この文書自身の説明・編集方針）は削る。
- 文面に**私的な実測値とマジックナンバーを書かない**（数値は台帳と報告へ）。本文には**一般則**を書き、その回の事情は理由に1行添えるまでに留める。

## 実装ごとの呼び名

| 本文の言い方 | ある実装での呼び名 |
|---|---|
| ハーネスのホーム | 環境変数 `HERMES_HOME`（既定 `~/.hermes`） |
| スキルのツリー | `<skills-root>/<category>/<name>/SKILL.md`＋`references/` |
| カテゴリの説明・一覧 | `DESCRIPTION.md` / `WHEN_TO_USE.md` |
| エージェント層の定義 | `SOUL.md`（プロファイル直下） |
| 毎ターン載る記憶 | `MEMORY.md` / `USER.md`（`memories/` 配下） |
| 詳細の置き場・在処 | `<memory-home>/details/*.md` と在処の一覧 |
| ツール定義の遅延 | `tools.tool_search.defer` に名前を並べる（config） |
| 索引の畳み込みの対象 | カテゴリ一覧を持つ設定キー（例: `agent.compact_skill_categories`） |
| 圧縮の発火点 | `compression.threshold`（文脈の割合） |
| 決定論的な刈り込み | `compression.proactive_prune_tokens`（0＝無効）＋`proactive_prune_min_reclaim_tokens`（最小回収量） |
| 刈り込みの対象になる大きさ | `proactive_prune_min_result_chars` |
| 末尾の保護 | `compression.protect_last_n`（無圧縮で残す件数） |
| 刈り込みが発火した印 | セッションの設定に書かれる再発火までの値（例: `_proactive_prune_rearm_tokens`） |

自分の実装の呼び名に置き換えて読んでください（**一般則が本体**、この表は補助）。
